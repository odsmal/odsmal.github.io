Emerging Interface Models in 2026

A review of generative interfaces, visible agents, multimodal input, spatial computing, and emerging GUI components.

Scope and maturity

Interfaces are becoming adaptive, multimodal, and capable of continuing delegated work without continuous user input.

Summary

  • Fixed screens are giving way to task-specific interfaces assembled around user intent.
  • Agent interfaces require visible state, limited authority, deliberate approval, and recovery controls.
  • Voice, vision, gaze, gesture, muscle signals, and spatial input should share a consistent focus and feedback model.
  • Trusted components can support dynamic composition while preserving semantics and safety.

A travel request may begin through smart glasses, expand into a comparison view on a laptop, and end with an agent preparing a booking. The interface should stop at the payment boundary, describe the proposed transaction, request approval, and provide a receipt with recovery options.

These capabilities already exist at different levels of maturity. This review separates released products from previews, emerging standards, and design proposals.

ReleasedAvailable in a released product or stable implementation, subject to platform and regional limits.
PreviewAnnounced, in beta, in developer preview, or being introduced gradually.
Emerging standardImplemented across an ecosystem, but still subject to technical and adoption changes.
Design proposalA component or principle proposed in this article rather than an established standard.

An effective adaptive interface remains understandable when its inference is incorrect.

From fixed to adaptive interfaces

Traditional graphical interfaces require users to learn a predefined information architecture. Current systems are changing this model in three ways:

  • Intent can replace navigation. Users describe an outcome without first locating the appropriate tool.
  • Commands can become delegation. Software plans and completes several steps, then returns when a decision is required.
  • Context extends beyond the screen. Voice, cameras, gaze, hands, wearables, and the physical environment supplement conventional input.

Visual interfaces remain necessary. Text is inefficient for comparison, precise adjustment, spatial relationships, monitoring, and consequential review. Conversation may establish intent, while a table, map, timeline, form, or editor supports inspection and revision.

Core requirement

When an interface changes between tasks, semantics, consent, system state, permissions, focus, feedback, and recovery must remain consistent.

Controlled generative interfaces

A controlled generative interface allows an agent to request a task-specific arrangement while the host application retains control of the component catalog, visual system, and execution boundary.

Google’s A2UI v0.9, released in April 2026, represents interface intent in a framework-independent format. The client maps that description to approved components and can update them as the conversation changes. The agent does not produce arbitrary executable code. In September 2026, the roadmap listed v0.9.1 as stable and v1.0 as a candidate; A2UI therefore remained an evolving open project rather than a universal standard.

MCP Apps, introduced in January 2026, allows tools to return sandboxed forms, dashboards, viewers, and workflows within an agent conversation. The host manages communication, theme, and permissions. OpenAI’s Apps SDK and interface guidance follow the same model: established controls and workspaces appear within the conversation when required.

Emerging

Declarative composition

The agent provides a specification; the host renders trusted components with established semantics and styling.

Released

Conversation-hosted applications

A tool returns a bounded interactive workspace without requiring a separate application.

Design proposal

Interface compiler

Intent, context, policy, and preferences produce a temporary, inspectable task interface.

Design requirement

Stable properties

Generated layouts preserve labels, reading order, user settings, exit paths, and a consistent action model.

A curated component catalog can preserve keyboard operation, semantics, focus, target size, and contrast more reliably than unrestricted generated HTML. It does not guarantee accessibility. Every state, focus transition, announcement, and complete task still requires testing.

Visible state for delegated work

A loading indicator is insufficient for work that may continue for minutes or hours, divide into subtasks, wait for information, cross applications, or approach a consequential action.

Android Halo, previewed in May 2026, proposed a persistent area that indicates whether an agent is working, operating in a live mode, or requesting attention. Its principal contribution is continuity: agent state remains visible across navigation.

Other systems for long-running work expose plans, checkpoints, questions, approvals, editable artifacts, and progress. This shifts UX from response presentation to delegation design. The interface should answer:

  • What goal did the system infer, and what remains unresolved?
  • What is happening now, what has finished, and what is waiting?
  • Which accounts, data, and tools are in scope?
  • Which actions are reversible, and which require approval?
  • How can the user pause, direct, correct, stop, or recover the work?

Frequent confirmation creates approval fatigue. A safer pattern combines a limited technical sandbox, a visible plan, and checkpoints at consequential boundaries. Each approval should state what will change, where, for whom, which data will be used, and whether the action is reversible.

Multimodal reference and input

Multimodal systems combine speech with a shared screen, camera view, recent selection, or spatial focus. Microsoft Copilot Vision, for example, allows a user to share an application, page, screen, or camera feed and discuss it by voice.

A central capability is deictic reference: resolving terms such as “this,” “there,” or “the second one” through shared attention. The system should identify the selected referent. If pointer, gaze, speech, and recent context conflict, the interface should expose the uncertainty rather than make an invisible assumption.

The interface should clearly identify the observed surface, indicate active sensing, provide an immediate stop control, and state when context is discarded. Essential functions also require alternatives to gaze, custom gestures, and voice.

Muscle signals and assistive input

Meta’s Neural Band uses surface electromyography at the wrist to translate muscle activity into actions such as selection and scrolling. It is muscle-signal input rather than mind reading, and it requires conventional alternatives when recognition, fit, mobility, or availability differs.

Apple’s Brain Computer Interface protocol allows specialist third-party hardware to send switch, keyboard, pointer, focus, and BCI-specific events to Apple platforms. It is an interoperability layer for assistive devices, not a general neural interface. New input methods become useful when they share the same focus, action, feedback, and fallback model as established input.

Spatial interface requirements

Spatial computing adds distance, depth, scale, comfort, and social visibility to interface design. Apple’s visionOS uses eyes and hands as primary input while supporting keyboards, trackpads, and accessibility hardware. Android XR guidance covers hand and eye tracking, voice, controllers, keyboards, mice, panels, orbiters, and spatial elevation. In September 2026, Compose for XR was in beta, while the glasses-focused Glimmer and Projected APIs remained in alpha.

A spatial panel presents two-dimensional content in space. An orbiter places a limited set of controls beside a panel. Distance-aware detail reduces information as viewing distance increases. An attention-safe overlay limits its visual field and avoids obscuring the environment.

visionOS guidance demonstrates that distance-aware components require more than proportional scaling: nearby widgets may expose detail and actions, while distant widgets retain only essential information. Android cautions against excessive orbiters, complex gestures, uncomfortable postures, and dependence on a single input method. Spatial design should prioritize legibility and comfort over immersion.

Integrated visual systems

Apple’s Liquid Glass and Google’s Material 3 Expressive use different visual conventions, but both integrate appearance, motion, feedback, and device form.

Liquid Glass applies a dynamic material to controls and navigation, adapting tint and separation to underlying content and changing as controls change state. Material 3 Expressive combines responsive components, stronger typography, dynamic color, spring motion, haptic feedback, live updates, and shapes adapted to round displays.

The significant development is perceptual feedback as structure. Motion communicates continuity, haptics confirm state changes, materials distinguish controls from content, and shape responds to the device. These systems still require restraint: transparency may reduce contrast, motion may distract or cause discomfort, and visual expression requires a stable hierarchy.

Native web interface controls

The web platform now supports interaction patterns previously implemented through custom JavaScript. Popovers use the top layer, support dismissal, and participate in focus management. CSS anchor positioning connects menus and tooltips to their triggers and provides alternatives near viewport edges. Declarative commands can control dialogs. Customizable native <select> elements support richer content while retaining form semantics and progressive fallback.

Safari 27 added customizable select support in September 2026 after Chromium’s implementation. Chrome’s 2026 interface update also documented element-scoped view transitions, state-preserving DOM moves, automatic contrast selection, experimental HTML in canvas, and proposed gesture-driven regions. These features remain at different levels of maturity.

Native platform support can improve the reliability of focus relationships, dismissal, positioning, semantics, state, adaptation, and interruption-safe movement. New capabilities should be introduced selectively and with progressive enhancement.

Components for delegated work

The following proposed components are not standardized controls. They identify recurring requirements when software infers intent or acts over time.

  1. Intent summaryAn editable statement of the system’s interpretation of the request.
  2. Ambiguity indicatorAn unresolved assumption about date, recipient, scope, or meaning that can be corrected directly.
  3. Delegation levelA persistent choice between suggesting, preparing, and acting within stated limits.
  4. Plan previewThe proposed steps, tools, data scope, checkpoints, and outputs shown before work begins.
  5. Activity indicatorA persistent status for working, waiting, paused, failed, complete, or requiring attention.
  6. Approval gateA decision point placed immediately before a consequential action.
  7. Action receiptA record of the change, location, time, inputs, provenance, and result.
  8. Recovery controlsNearby options to pause, correct, undo, restore, retry, or request support.

An agent interface should communicate state, authority, uncertainty, and recovery rather than rely on visual personification.

Design principles

Adaptive interfaces should be assessed through coherence, control, and reliability rather than novelty.

  1. Generate arrangements rather than arbitrary behavior. Models may compose trusted components, while the host retains control of execution and semantics.
  2. Make inferred intent editable. Present the system’s interpretation before converting it into a plan.
  3. Keep agent activity visible and unobtrusive. State should persist without continuously demanding attention.
  4. Request approval at consequential boundaries. Combine technical limits with risk-based approval rather than repeated confirmation.
  5. Represent uncertainty explicitly. Expose relevant referents, assumptions, sources, and confidence.
  6. Provide consistent recovery. Pause, correction, undo, restoration, and receipts are primary controls.
  7. Provide equivalent input methods. Gaze, gesture, voice, haptics, and spatial placement should expand access rather than restrict it.
  8. Account for the physical environment. Consider bystanders, privacy, safety, social visibility, lighting, noise, and divided attention.

The quality of an adaptive interface depends on how clearly it communicates its behavior.
