Purpose and terminology

This specification defines the current implementation and the requirements for future revisions.

It documents the website as implemented on 29 September 2026. When the code and specification differ, determine the intended behavior and update both in the same revision.

Site map

The index is the single public entry point. Every project card and project title in the table leads to a destination page. The compatibility route exists only for old links.

  • 1Entry point — project discovery begins on the index.
  • 2Project destination — every listed item has a real page URL.
  • 3Article subtype — structured long-form analysis with a summary, contents navigation, references, and optional interactive examples.
  • 4Report subtype — formal reference with explicit scope and method, findings, recommendations, references, and optional labs.
  • 5Specification subtype — long-form visual reference using the shared reading shell.
  • 6Support routes — generic details and compatibility links are not primary index entries.

File structure and ownership

There is no build step and no third-party dependency. A browser reads the HTML, CSS, and JavaScript directly. File ownership runs from broadest to narrowest: tokens → base → shared components → page-family styles → page-specific styles.

Design foundations

Layout and typography

  • Shell: .shell is centered, has a maximum width of 1180px, and keeps 17px side gutters; at 590px and below the gutters become 12px.
  • Sans serif: Trebuchet MS and Arial for interface text, headings, and buttons.
  • Serif: Georgia and Times New Roman at 21px/1.65 for .lead and classless paragraphs placed directly inside long-form sections. Hero summaries use their responsive .dek scale; lists, cards, controls, and captions keep their own sizes.
  • Monospace: Courier New for eyebrows, labels, status, and structural references.
  • Shape language: cards and work surfaces use modest 7–14px corners; identity and navigation controls use pill corners; category and view controls remain rectangular.

Theme tokens

The dark canvas, surface, and inset-surface values are shared across pages. Dark accents are page-specific: the index and interface-models article use #aeb4ff, the WCAG report uses #8ecbff, this specification uses #8ed6c4, the family-tree visualization uses #a6d49f, and the table-history article uses #e7c58d.

Token rule

Use semantic tokens for established color roles and update both themes together. The dark theme uses a cool-charcoal surface hierarchy with soft white text; page accents retain project identity and required contrast.

Shared top bar

The top bar is the same component family on every real page. It has a 68px minimum height; the index uses 10px vertical padding, and compact subpages use 8px top padding. On the index, About and the theme selector are direct children of .topbar--index. Subpages add the All projects back link and wrap About plus the theme selector in .topbar-actions. There is no bottom border.

About disclosure

The About panel introduces Kristoffer Johansson, briefly describes his interface design work and the site's purpose, and defines “bös” in a dashed lexicon note. It opens from the button, closes from the same button, closes on outside click, and closes on Escape. Escape returns focus to About. It is a nonmodal disclosure: the rest of the page remains available and there is no focus trap. At narrow widths, the panel aligns to both edges of the shared top bar and scrolls internally when the available viewport height is limited.

Theme selector

Sun selects light mode and the solid moon selects dark mode. The selected segment is visually filled and programmatically exposed through aria-pressed="true". The moon inherits the current foreground color so its appearance is consistent on every page.

Main page anatomy

The index is a compact archive, not an editorial page. Its job is to identify the collection, let people narrow it, change its representation, and open a project.

Control order

  1. Category filters remain together on the left.
  2. The card/table selector is pushed to the right with margin-left: auto.
  3. The result count follows the controls and uses aria-live="polite".
  4. Only one collection view is visible; the other receives the shared .hidden utility.

Project cards and table

Card view

The card is the primary visual representation. The whole boundary is one link, so title, summary, visual, and metadata all open the same project. With no secondary tag, the card label uses its category name.

Table view

The table is the compact comparison representation. It uses real column headers and the project name as each row header. Row typography mirrors the corresponding card text; only the linked project name remains underlined. Category labels reuse the card label’s raised surface background, borderless shape, padding, and typography.

Project subpages

The articles, report, visualization, and this specification share the long-form page shell. The generic project template uses a shorter detail shell with the same top-bar controls and return route.

Eyebrow pattern

Every published project uses “Category · Published D Mon YYYY · Author: Name” in the eyebrow. Long-form heroes do not use metadata pills, separate bylines, or boxed summary and timeline strips. “Field note” and “Snapshot” are not current eyebrow terms.

Generic project detail

project.html?project=<slug> is populated by project.js. It has a hero, large project visual, facts, project notes, a useful finding, and Project index/Next navigation. It remains available for future small builds and experiments, but those dormant data records are not part of the visible archive.

Required state semantics

  • Toggle choices: use aria-pressed; exactly one card/table view and one theme are pressed.
  • Disclosure: About uses aria-expanded and aria-controls.
  • Hidden regions: use the shared .hidden class, which removes content from layout and the accessibility tree.
  • Focus: the global dual white/black ring must not be removed or clipped.
  • Dynamic result: count or lab output uses a restrained polite live region when an announcement is useful.
  • Unavailable result: show the textual empty state “No projects are available in this category.”

Naming and dates

  • Site title: Blandat bös.
  • Index heading: Project index.
  • Long-form eyebrow: Category · Published D Mon YYYY · Author: Name.

Editorial style

  • State the subject, scope, and conclusion directly.
  • Use descriptive headings and active constructions.
  • Remove repetition, conversational asides, and unsupported emphasis.
  • Retain qualifications, definitions, source links, and safety-relevant context.
  • Use captions and control text that describe function rather than mood.

Interaction and behavior

Theme

Persisted choice

theme.js reads field-notes-theme from local storage. With no saved choice it follows the operating system at page load. Choosing light or dark saves the explicit choice across pages.

About

Disclosure, not dialog

about.js toggles the panel, closes it on outside click, and closes it on Escape with focus returned to the trigger.

Filter

Type-based collection

Selecting a category updates aria-pressed, filters the trusted project data, redraws the active representation, and updates the polite result line.

View

Card or table

The two controls change only the representation. Filter state remains. The selection is in memory and resets to cards after reload.

Navigation

Pages, not dialogs

Cards and project table titles use normal links. Project content opens as a URL-addressable subpage and the browser Back action remains meaningful.

Interactive labs

Immediate examples

Every input has a visible label. Generated outcomes appear next to the controls and important textual changes are announced politely.

Keyboard model

  • Tab and Shift + Tab move through links and controls in document order.
  • Enter activates links and focused buttons; Space activates buttons.
  • Escape closes the About panel when open.
  • The skip link becomes visible on focus and moves focus to the primary page content.
  • Native select, radio, range, and table behavior must be preserved instead of recreated.

Accessibility contract

Accessibility is a release requirement.

The published site targets WCAG 2.2 Level AA in every theme, viewport, view mode, project page, interactive example, empty state, and complete task. The preferred 44 × 44px target area is an added usability practice; the WCAG 2.2 minimum is 24 × 24px unless a documented exception applies.

01

Structure

Use one clear h1, hierarchical headings, semantic landmarks, real lists, real tables, and real links or buttons for their native purpose.

02

Keyboard

Every operation works without pointer input. Focus order follows reading order, remains visible, and never enters hidden content.

03

Names and state

Icon-only controls have accessible names. Pressed, expanded, selected, error, and status information is available in text or semantics.

04

Contrast

Normal text targets at least 4.5:1, large text 3:1, and meaningful control boundaries and focus indicators 3:1 against adjacent colors.

05

Targets

Primary shared controls are at least 44px high, with 48px used for About, Back, filters, and segmented-control containers.

06

Zoom and reflow

Content remains usable at 200% text zoom and 400% browser zoom. Diagrams reflow; they do not shrink labels into unreadable miniatures.

07

Motion

Project cards do not animate. Smooth scrolling is disabled when reduced motion is requested. New animation needs a clear purpose and a reduced-motion alternative.

08

Color independence

Status, selection, and category never rely on hue alone. Text, shape, border, placement, or programmatic state carries the same meaning.

09

Dynamic content

Use polite announcements only for meaningful changes. Avoid interrupting reading, moving focus without request, or repeating visible text excessively.

10

Illustrations

Visual diagrams have captions and complete text keys. Decorative wireframes are hidden from assistive technology only when the adjacent key is equivalent.

Minimum review

Keyboard-only pass, visible-focus pass, light and dark contrast check, 400% reflow check, reduced-motion check, and a screen-reader spot check of navigation, toggles, tables, and dynamic results.

Known architectural boundaries

  • The shared top-bar markup is duplicated in static pages. Its styling and behavior are shared, but changing its HTML requires updating each real page.
  • The custom article and report are hand-authored HTML. The index and generic detail page are rendered from JavaScript data.
  • project.js retains dormant older project records that are not listed on the index.
  • Index filter and view choices are not persisted; the theme choice is persisted.
  • Project rendering uses trusted local data with innerHTML. Do not place untrusted user input in those objects without escaping it.
  • Page-specific token sets intentionally give long-form projects distinct accents while shared controls keep the same construction.

Release checklist

Run the relevant checks after every revision. Run the complete list before publishing or making a new archive.

Structure

  • All local href and src targets exist.
  • No duplicate IDs appear on a page.
  • HTML headings and landmarks follow a logical order.
  • New project data has a valid category, tag, URL, and approved status.
  • Main and subpage top bars use the shared markup.

Interaction

  • About opens, closes outside, and closes with Escape.
  • Theme persists while moving between pages.
  • Every category filter returns the expected projects and count.
  • Card/table switching causes no horizontal layout shift.
  • Every project card and table title opens its subpage.

Accessibility

  • Skip link works and becomes visible on focus.
  • All controls are keyboard operable with visible focus.
  • Pressed and expanded states match the visible state.
  • Light and dark palettes meet required contrast.
  • Content reflows at 400% without two-dimensional page scrolling.
  • Tables have scoped headers and labelled scroll regions.
  • Illustrations have captions and equivalent text keys.

Responsive and output

  • Review wide, 860px, 640px, and 590px layouts.
  • Long titles and labels wrap without collision.
  • About panel remains inside the viewport.
  • Reduced-motion mode removes smooth scrolling.
  • Print keeps reference content and readable borders.
  • Source and mirrored website folder contain matching files.
